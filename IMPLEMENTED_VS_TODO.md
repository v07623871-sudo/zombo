## Что действительно осталось и почему это важно

### Обязательно (высший приоритет)

- Полноценная админская панель: есть только `GET /api/admin/summary`. Нужны поисковые экраны, модерация, журнал действий, транзакционно защищённое управление игроками и событиями.
- Системный аудит и регрессионные тесты, особенно многопользовательские одновременные запросы на рынок, рейды, КВ и зачисление Stars. Не полагаться на зелёный `/health` как доказательство корректности всех механик.
- Безопасная схема миграций PostgreSQL: в проекте есть `Base.metadata.create_all()`, но этого недостаточно для изменения существующих колонок. Изменять без сброса данных.
- Проверенная стратегия резервного копирования и восстановления PostgreSQL; резервные копии не следует объявлять «автоматическими», пока это реально не настроено.
- Дополнительные меры устойчивости Telegram-бота/оплат: таймауты, повторные webhook апдейты, логирование без токенов, идемпотентность покупок, запрет фальшивых/чужих зачислений.

### После обязательного

- Улучшение UX и мобильных экранов с **обязательным сохранением нынешнего визуального стиля и арта**; более информативные боевые результаты, подсказки расходов, прогресса, редкостей, задач.
- Кооперативные экспедиции на 12 часов, дополнительные классовые синергии, клановые задания, разнообразные случайные события и PvE-контент.
- Уведомления от Telegram-бота о готовности рейда, продаже экипировки, начале КВ, сюжетных событиях (при наличии разрешений).
- Мониторинг и диагностика ошибок, лимиты размеров логов/истории, пагинация, антиспам, ограничение повторных нажатий.
- Баланс экономики, антифарм и тестирование клановых войн с реальными участниками; адекватное поведение при нехватке игроков и долгом отсутствии онлайна.

### Специально НЕ делать в ущерб главному

- Новый интерфейс и новый арт вместо понравившихся персонажей.
- Полный рерайт с FastAPI на PHP/React/Next.js.
- Несогласованные покупки, рекламные системы, тяжёлые зависимости и ложный «античит» только на стороне браузера.
- Ненужную генерацию изображений, на которую уходит бюджет и которая ломает стиль.
- Демо-кнопки и фиктивные функции.

## Быстрая проверка после изменений

```bash
python -m pip install -r requirements.txt
python -m pip install pytest
python -m pytest -q tests
node --check static/app.js
# Локально с безопасными env-переменными / отдельной тестовой БД:
uvicorn app:app --host 127.0.0.1 --port 8080
# curl http://127.0.0.1:8080/health
```

Нельзя включать `DEMO_MODE=1` в production; нельзя засылать на Railway тестовую БД поверх живой.

## Что ассистент сделает после твоей сдачи

Получит единый архив из Codex, сравнит его с актуальным `main`, проверит, что нет секретов и опасных миграций, выполнит доступные тесты, затем только после этого внесёт изменения в `GitHub v07623871-sudo/zombo` и проверит сборку Railway. Если за это время проект изменится — изменения нужно корректно объединить, а не затереть.
