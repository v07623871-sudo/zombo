# Обновление GitHub / Railway — оператору

Версия 0.9.3 добавляет касание портрета зомби для обычного удара в корпус и отображение результата хода. Новых таблиц, колонок и переменных окружения нет. Версия 0.9.2 добавила навигацию Mini App, три сортировки рейтинга и текстовые команды Telegram-бота. Версия 0.9.1 исправила смену трёхдневного цикла мирового босса при прямой атаке. Инструкция по резервной копии и миграции ниже остаётся обязательной при обновлении с 0.8.x. После деплоя проверьте один бой касанием и кнопкой выбора цели, а также `/top`, `/top kills`, `/top pvp`, `/quests`, `/boss`, `/raid`, `/expedition` в тестовом чате бота.

1. Сверьте этот архив с актуальной веткой `main` и объедините новые изменения, если после исходного коммита `d0fafdd8f15f30ffc1c567d2fe2b1012154a3562` репозиторий менялся. Не перезаписывайте живые `.env` и PostgreSQL-данные.
2. До деплоя сделайте резервную копию с установленными клиентскими `pg_dump` и `pg_restore` и доступным `DATABASE_URL`: `python scripts/backup_postgres.py --output backup-YYYYMMDD.dump`. Скрипт не перезаписывает существующий файл, проверяет формат и не выводит пароль. Храните копию вне Railway и протестируйте восстановление на отдельной пустой БД.
3. На тестовой копии PostgreSQL запустите `python scripts/migrate.py`, затем `python -m pytest -q tests`, `node --check static/app.js`, проверьте `/health`, `/ready` и Mini App. Скрипт только создаёт недостающие таблицы через SQLAlchemy и остановится, если у существующей таблицы не хватает ожидаемых колонок. Новые таблицы относительно 0.8.0: `admin_audit`, `star_invoices`, `payment_reviews`, `expedition_runs`, `expedition_members`. Существующие таблицы/строки не удаляются.
4. Убедитесь, что Railway содержит `BOT_TOKEN`, `PUBLIC_URL`, `TELEGRAM_WEBHOOK_SECRET`, `DATABASE_URL`, а `ADMIN_IDS` перечисляет только реальные Telegram ID доверенных администраторов. `DEMO_MODE=0`. На первом этапе оставьте `ACCEPT_LEGACY_STAR_INVOICES=1` (значение по умолчанию), чтобы выданные до обновления ссылки Stars принимались. Устанавливайте `0` только после вывода старых ссылок из обращения и сверки оплат; платежи по ним после отключения появятся в админском списке «На проверку» без автоматического зачисления. Новых обязательных env-переменных нет. Запустите миграцию для рабочей БД после проверки резервной копии и перед/вместе с деплоем кода. Измените GitHub через проверенный PR/коммит, затем проверьте запуск Railway.
5. После деплоя проверьте авторизацию обычного игрока (403 на `/api/admin/*`), экран администратора, `/ready`, `/start`, `/daily` и один тестовый сценарий без реальных платежей. Не повторяйте оплату Stars без контролируемого тестового плана.

Откат кода: вернуть предыдущий проверенный релиз Railway/GitHub. Добавленные `admin_audit`, `star_invoices`, `payment_reviews`, `expedition_runs` и `expedition_members` можно оставить — старая версия их игнорирует. Восстановление дампа требуется только при повреждении данных и сначала должно быть проверено на отдельной БД. Скрипта, который удаляет старые таблицы, нет. Автоматическое расписание резервных копий здесь не включено. При откате во время 12-часовой экспедиции её состояние останется в БД; обновлённый код сможет завершить её по таймеру после повторного развёртывания.

## ZOMBO 0.10 production security and backup

New additive SQL tables: `api_quotas` (per-player request counters), `telegram_receipts` (Telegram update deduplication and leases). No existing player or billing column changed. All 63 local tests passed. New backup worker in `ops/backup/` uses Docker `postgres:18-alpine`, private Railway Bucket, and cron `0 3 * * *` UTC. In the existing Railway production project, a 70 872-byte backup was uploaded and restored in a temporary PostgreSQL service successfully on 2026-10-11. Temporary services were removed. Cron logs and bucket retention should be monitored each day. `ADMIN_IDS` still needs owner Telegram ID to allow GM access.
